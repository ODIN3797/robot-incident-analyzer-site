How to read an RIA report.

The public sample is a real report produced by the RIA engine, not a mockup. Its recording data is entirely synthetic, so the numbers below describe the analyzer's behaviour on fictional inputs — not measured robot-fault accuracy.

3Input files
19Candidate events
17Investigation findings

These counts are pinned in the published provenance record (demo/provenance.json). The sample was generated by analyzer version 0.7.58. The private, manually approved evaluation package is a separate 0.7.59 build, so its output can differ from this sample.

What to inspect, in order

  1. A candidate finding: what was flagged, at which timestamp, and how severe the analyzer judged it.
  2. Its evidence: the observations, signals and event rows the finding links to.
  3. The uncertainty: which context was missing, so the finding could not be confirmed from this recording.

What the report does not tell you

  • It does not name a verified physical root cause.
  • A missing finding is not proof that the robot behaved correctly.
  • Correlation inside a window is a review candidate, not a diagnosis.
  • Numbers from fictional inputs do not establish real-world precision or recall.

Good first exercise

Open the report, pick the highest-severity finding, and answer three things in a sentence each: what was flagged, which evidence supports it, and what would still need checking on the real robot.

If all three answers are clear, the workflow is doing its job for you.
